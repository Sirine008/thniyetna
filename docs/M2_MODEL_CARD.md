# M2 model card — `m2-risk:2026.10.11-2054`

Generated by `python -m prediction.report` from `reports/m2/`. Do not edit by hand.

## Task
Predict, for each governorate and day, the probability of at least one recorded road accident
(`accident_flag`), the expected number of accidents and the probability of a fatal accident.
Segment RiskScores are derived from these forecasts (see `segment_risk.py`).

## Data
- Accidents: 69,394 records, 2015-01-01 → 2026-09-27 (no GPS; governorate on every record).
- Weather: one reference station, 2022-04-01 → 2026-10-08.
- Panel: 39,360 governorate-days, 2022-04-02 → 2026-09-27.
- Temporal split: train ≤ 2023-12-31, validation ≤ 2024-12-31, test → 2026-09-27. No random split.
- Every feature of day t is computed from data up to t-1 (unit-tested in `tests/test_m2_core.py`).

## What the results mean (limits)
- The model mainly separates *which governorates* are risky; within one governorate the median ROC-AUC is 0.524 — day-to-day timing is close to unpredictable with these inputs.
- Accident history carries almost all the signal. With one national weather station, weather features add nothing (see ablation); per-governorate weather (`fetch_weather.py`) is the next experiment.
- Trees (RF, XGBoost) do not beat the logistic regression significantly at this granularity.
- Segment-level accident risk is an *allocation* (exposure × class weight), not a segment-level model: accidents have no coordinates. It ranks road classes and lengths correctly but cannot single out a black spot.
- The M1 condition component is a documented rule-based prior until labelled defect histories exist (`condition_model.py`).
- The accident export ends before the scoring date: history features use the last observed day and the API reports `history_staleness_days`.
